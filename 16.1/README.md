# Задание "Работа с LLM через API"

**Преподаватель**: Даниил Корбут  

В этом задании вы сделаете первый реальный шаг в работе с большими языковыми моделями через API. Вы не просто изучите теорию — вы напишете код, который заставляет модель возвращать не просто текст, а строгие структурированные данные в формате JSON, которые можно сразу использовать в программе.  

**Почему это важно?** Умение работать с LLM через API — базовый навык современного разработчика и специалиста по AI. Интеграция языковых моделей в реальные приложения открывает возможности для автоматизации, создания умных сервисов и повышения продуктивности.  

**Выполнив это задание, вы:**  
● настроите окружение для работы с несколькими языковыми моделями;  
● научитесь формировать корректные запросы к LLM через HTTP API и обрабатывать полученные ответы в Python-коде;  
● реализуете прикладной сценарий: построите мини-пайплайн для автоматического разбора резюме и вакансий, а также сравните несколько LLM по скорости и качеству извлечения структурированных данных.

## Описание задания
Реализуйте пайплайн структурированного извлечения данных с использованием Groq API. В итоге ваша программа должна:  
1. извлекать структурированный JSON-профиль из текста резюме с помощью JSON-режима;
2. обрабатывать батч из 7 резюме и фильтровать кандидатов по заданным критериям;
3. сравнивать скорость и качество нескольких LLM-моделей на одной задаче;
4. реализовать парсер вакансий по той же схеме. Решение оформите в Jupyter Notebook, следуя инструкции ниже.

## Инструкция к выполнению
**Шаг 1.** Получите API-ключ Groq: зайдите на console.groq.com/keys, зарегистрируйтесь и создайте ключ в разделе API Keys.  
**Шаг 2.** Используйте учебный ноутбук. Установите зависимости: выполните pip install groq python-dotenv в терминале.  
**Шаг 3.** Создайте файл .env в папке с ноутбуком и добавьте туда строку GROQ_API_KEY=ваш_ключ.  
**Шаг 4.** Откройте предоставленный шаблон notebook praktika_groq_structured.ipynb.  
**Шаг 5.** Последовательно выполните ячейки разделов 1–4 и убедитесь, что все работают без ошибок.  
**Шаг 6.** Выполните задания раздела 5: реализуйте 5 фильтров кандидатов.  
**Шаг 7.** Запустите раздел 6 (сравнение моделей) и письменно ответьте на аналитические вопросы.  
**Шаг 8.** Реализуйте функцию parse_vacancy() для всех 3 тестовых вакансий в финальном задании.

- Параметр response_format={'type': 'json_object'} заменен на json_schema со строгой схемой, так как GigaChat API не поддерживает тип json_object (выдает ошибку 400).
- В разделе 6 сравнивались модели GigaChat (Lite, Pro, Max), так как моделей Llama/Mixtral в GigaChat нет.
- В шаблоне ноутбука было только 3 вакансии (хотя в чек-листе указано 5), функция parse_vacancy протестирована на всех 3 имеющихся.
